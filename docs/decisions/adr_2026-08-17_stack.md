# ADR-001 | What application stack should Cluestone be built from?

**Status:** Accepted
**Date:** 2026-08-17

## Context

Cluestone is intended to support web, Android, iPhone, and iPad. The application should share as much implementation as practical between platforms while still allowing platform-specific interfaces and behavior where appropriate. Because Cluestone is also a learning and portfolio project, reducing duplicated application logic and development effort is desirable.

## Decision

Cluestone will use React Native with Expo and TypeScript as its primary application stack.

This allows the web, Android, and iOS/iPadOS applications to share most application logic and UI components while retaining the ability to introduce platform-specific implementations where necessary.

## Alternatives Considered

### Kotlin

Kotlin Multiplatform was considered because of its strong native-platform support and ability to share application logic. It was not selected because Cluestone places significant importance on sharing UI implementation across web and mobile, and React Native/Expo provides a more direct path to a shared application codebase across all three targets. Kotlin was also discarded because research showed that it does not have as robust support online yet.

## Consequences

- Most application code will be written in TypeScript/React.
- UI and business logic can generally be shared across web, Android, and iOS.
- Build/distribution tooling will likely center on Expo/EAS. Expo currently provides tooling for producing and distributing Android and iOS binaries.
- The project becomes dependent on the React Native/Expo ecosystem.
